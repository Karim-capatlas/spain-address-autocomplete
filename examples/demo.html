1 · Web Component

The <address-search-es> StencilJS custom element is framework-agnostic — it works in any HTML page, and generates typed React, Vue, and Angular wrappers automatically.

Live Demo

Type a street name, municipality, or postal code. The widget groups results by municipality and supports keyboard navigation.

Attributes

All properties are reflected as HTML attributes and can be set declaratively or via JavaScript.

<!-- Proxy mode (recommended for production) --> <address-search-es endpoint="https://calle.alami.es/api/address-search" placeholder="Calle, municipio, código postal…" detect-cp scope-provincia="28" max-groups=8 group-limit=3 ></address-search-es> <!-- Direct Typesense mode --> <address-search-es typesense-host="127.0.0.1" typesense-port=8108 typesense-api-key="xyz" typesense-protocol="http" ></address-search-es>

Events

The widget emits custom events that you can listen to from the light DOM.

const widget = document.getElementById('address-search'); // Fired when a user selects an address widget.addEventListener('addressSelected', (e) => { const addr = e.detail; console.log(addr.label, addr.codigo_postal); // { via_tipo, via_nombre, via_nombre_completo, // municipio, municipio_id, provincia, provincia_id, // comunidad_autonoma, codigo_postal, label, highlights } }); // Fired when the selection is cleared widget.addEventListener('addressCleared', () => { ... }); // Fired when the province scope changes widget.addEventListener('scopeChanged', (e) => { console.log(e.detail.provincia); }); // Fired on errors widget.addEventListener('error', (e) => { console.error(e.detail.message, e.detail.code); });

Imperative API

Drive the widget programmatically via @Method decorators.

const widget = document.getElementById('address-search'); // Clear the widget await widget.clear(); // Get the current selection const addr = await widget.getSelection(); // Set a selection programmatically await widget.setSelection({ label: 'Calle Gran Vía, Madrid (28013)', via_tipo: 'Calle', via_nombre: 'Gran Vía', municipio: 'Madrid', municipio_id: '28079', provincia: 'Madrid', provincia_id: '28', codigo_postal: '28013', });

React / Vue / Angular Wrappers

Stencil's @stencil/react-output-target generates typed framework wrappers from the single component source.

// React (auto-generated) import { AddressSearchEs } from '@spain-address/widget/react'; function App() { return ( <AddressSearchEs endpoint="https://calle.alami.es/api/address-search" detectCp=={true} onAddressSelected=={(addr) => console.log(addr)} /> ); }

2 · Proxy / BFF API

The Hono-based backend-for-frontend keeps Typesense credentials server-side. The browser widget calls this endpoint — never the search backend directly.

Search Addresses

Fuzzy street search with municipio grouping, province filtering, and postal code detection.

# Text search — returns grouped results curl "https://calle.alami.es/api/address-search?q=gran%20via" # Postal code lookup — returns all streets in that CP curl "https://calle.alami.es/api/address-search?cp=28013" # With province filter curl "https://calle.alami.es/api/address-search?q=calle&provincia=28" # With municipality filter curl "https://calle.alami.es/api/address-search?q=gran&municipio=28079" # Pagination and grouping curl "https://calle.alami.es/api/address-search?q=plaza&per_page=10&group_limit=5"

Response Shape

The response matches SearchResult from @spain-address/core.

{ total: 131, took_ms: 12, groups: [ { municipio_id: "28079", municipio: "Madrid", provincia: "Madrid", provincia_id: "28", codigo_postal: "28013", found: 42, items: [ { id: "a3f1b2c4d5e6f7a8", via_tipo: "Calle", via_nombre: "Gran Vía", via_nombre_completo: "Calle Gran Vía", municipio: "Madrid", codigo_postal: "28013", label: "Calle Gran Vía, Madrid (28013)", highlights: [{ field: "via_nombre_completo", snippet: "Gran Vía" }] } ] } ] }

Health Check

curl "https://calle.alami.es/health" # → {"ok": true}

3 · Cascade API

Standalone Hono server for the provincia → municipio → código postal dropdown cascade. Replaces the external geoapi.es router with local sub-ms lookups backed by a dedicated cascade_es Typesense collection.

Endpoints

Method Endpoint Description
GET /api/geo/provincias Returns all 52 provinces with {code, name, ccaa}
GET /api/geo/municipios?provincia=28 Returns all municipalities for a province
GET /api/geo/cps?municipio=28079 Returns all postal codes for a municipality
GET /api/geo/validate-cp?municipio=28079&cp=28001 Validates that a CP belongs to a municipality

Usage Examples

# Get all provinces curl "https://calle.alami.es/api/geo/provincias" # → [{ code:"28", name:"Madrid", ccaa:"Comunidad de Madrid" }, ...] # Get municipalities in Madrid curl "https://calle.alami.es/api/geo/municipios?provincia=28" # → [{ code:"28079", name:"Madrid", ccaa:"Comunidad de Madrid" }, ...] # Get postal codes for Madrid city curl "https://calle.alami.es/api/geo/cps?municipio=28079" # → ["28001", "28002", "28003", ..., "28013", ...] # Validate a postal code curl "https://calle.alami.es/api/geo/validate-cp?municipio=28079&cp=28001" # → {"valid":true,"ineCode":"28079"}

4 · MCP Server

Drop-in stdio MCP tools for LLM pipelines. Spawnable from Claude Desktop, Cursor, or any parent OCR pipeline. Implements the JSON-RPC handshake over newline-delimited JSON on stdin/stdout.

Tool: normalize_address

Normalize a noisy Spanish address string (e.g. from DNI/TIE OCR) into structured fields. Returns the single best match.

# MCP JSON-RPC request { jsonrpc: "2.0", id: 1, method: "tools/call", params: { name: "normalize_address", arguments: { text: "calle gran via 12 madrid", provincia_id: "28" } } } # Response { jsonrpc: "2.0", id: 1, result: { content: [{ type: "text", text: "{\n \"via_tipo\": \"Calle\",\n \"via_nombre\": \"Gran Vía\",\n \"via_nombre_completo\": \"Calle Gran Vía\",\n \"municipio\": \"Madrid\",\n \"municipio_id\": \"28079\",\n \"provincia\": \"Madrid\",\n \"provincia_id\": \"28\",\n \"comunidad_autonoma\": \"Comunidad de Madrid\",\n \"codigo_postal\": \"28013\",\n \"label\": \"Calle Gran Vía, Madrid (28013)\",\n \"confidence\": \"exact\"\n}" }] } }

Tool: search_addresses

Search the Spanish street index (749K records). Returns ranked matches with municipio grouping.

# MCP JSON-RPC request { jsonrpc: "2.0", id: 2, method: "tools/call", params: { name: "search_addresses", arguments: { query: "plaza mayor", per_page: 5, provincia_id: "28" } } } # Response { jsonrpc: "2.0", id: 2, result: { content: [{ type: "text", text: "{\n \"total\": 131,\n \"groups\": [\n {\n \"municipio_id\": \"28079\",\n \"municipio\": \"Madrid\",\n \"provincia\": \"Madrid\",\n \"found\": 42,\n \"items\": [{ ... }]\n }\n ]\n}" }] } }

Configuration

Add to .mcp.json or your IDE's MCP settings:

{ "mcpServers": { "spain-address": { command: "node", args: ["/path/to/packages/mcp/dist/cli.js"], env: { "TYPESENSE_HOST": "127.0.0.1", "TYPESENSE_PORT": "8108", "TYPESENSE_API_KEY": "xyz" } } } }

5 · ETL Pipeline

The INE Callejero ETL pipeline downloads, parses, normalizes, deduplicates, and outputs the search index. Processes 88K+ raw TRAM rows into 37K+ structured records per province.

Run the Pipeline

# Download and process INE Callejero data pnpm exec tsx packages/etl/src/index.ts run \ --year 2026 --month 1 --provinces 28 # Validate the output pnpm exec tsx packages/etl/src/index.ts validate \ packages/data/snapshots/callejero_2026-01_28.jsonl # Process all provinces (national index) pnpm exec tsx packages/etl/src/index.ts run \ --year 2026 --month 1

Output

The pipeline produces a gzipped JSONL file with 749,261 records. Each record contains:

{ id: "a3f1b2c4d5e6f7a8", via_tipo: "Calle", via_nombre: "Gran Vía", via_nombre_completo: "Calle Gran Vía", municipio: "Madrid", municipio_id: "28079", provincia: "Madrid", provincia_id: "28", comunidad_autonoma: "Comunidad de Madrid", codigo_postal: "28013", label: "Calle Gran Vía, Madrid (28013)", lat: 40.42, lon: -3.70 }

6 · Typesense Indexing

Bulk-import the ETL output into Typesense. Two collections: callejero_es (749K street records) and cascade_es (18K province/municipality/postal code records).

Import Commands

# Import the street index (749,261 docs) pnpm typesense:import -- \ --snapshot packages/data/snapshots/callejero_2026-01.jsonl.gz \ --drop \ --batch-size 1000 # Import the cascade index (18,285 docs) pnpm cascade:import -- \ --snapshot packages/data/snapshots/callejero_2026-01.jsonl.gz \ --drop

Verify

# Check street index curl -s -H "x-typesense-api-key: xyz" \ "http://127.0.0.1:8108/collections/callejero_es" | node -pe "JSON.parse(require('fs').readFileSync(0,'utf8')).num_documents" # → 749261 # Check cascade index curl -s -H "x-typesense-api-key: xyz" \ "http://127.0.0.1:8108/collections/cascade_es" | node -pe "JSON.parse(require('fs').readFileSync(0,'utf8')).num_documents" # → 18285

7 · Architecture

The system is composed of four layers: the browser widget, the BFF proxies, the Typesense search engine, and the MCP server.

Client Layer

<address-search-es> widget · React/Vue/Angular wrappers · MCP clients (Claude, Cursor)

▼

BFF Layer

@spain-address/proxy — fuzzy street search · @spain-address/cascade — provincia/municipio/CP dropdown · Both Hono HTTP servers

▼

Search Engine

callejero_es (749K docs) · cascade_es (18K docs) · Typesense HTTP/REST · Faceted filtering, infix search, grouping

▼

Data Layer

INE Callejero (Jan 2026) · 749,261 streets · 52 provinces · 8,106 municipalities · 10,127 postal codes · INE Municipios (UP) master

8 · Deployment

Production deployment runs on a single OVH VPS behind a Cloudflare Tunnel. Total cost: under €5/month.

Quick Start

# Clone and install git clone https://github.com/Karim-capatlas/spain-address-autocomplete.git cd spain-address-autocomplete pnpm install --frozen-lockfile # Build the workspace pnpm build # Start Typesense (Docker) docker compose up -d typesense # Import both indexes pnpm typesense:import -- --snapshot packages/data/snapshots/callejero_2026-01.jsonl.gz --drop --batch-size 1000 pnpm cascade:import -- --snapshot packages/data/snapshots/callejero_2026-01.jsonl.gz --drop # Start the BFFs pnpm --filter @spain-address/proxy start # port 8787 pnpm --filter @spain-address/cascade start # port 5978

Cloudflare Tunnel

The demo hostname calle.alami.es routes through a Cloudflare Tunnel — no open inbound ports, automatic TLS.

# Tunnel routes (dashboard) # Path ^/api/geo → localhost:5978 (cascade) # Catch-all → localhost:8787 (proxy) # Widget config for Pages <address-search-es endpoint="https://calle.alami.es/api/address-search" ></address-search-es>

9 · Package Overview

The monorepo is organized into focused packages, each with a single responsibility.

@spain-address/etl

INE ZIP downloader, TRAM parser, UP municipio derivation, normalize/merge/dedupe, JSONL+gzip writer, CLI.

pnpm exec tsx packages/etl/src/index.ts run --year 2026 --month 1 --provinces 28

@spain-address/core

Shared types (AddressRecord, SearchResult) + backend-agnostic searchAddresses + createSearchClient factory (Typesense default, Upstash opt-in).

@spain-address/typesense

callejero_es collection schema + bulk-import CLI.

@spain-address/widget

StencilJS custom element <address-search-es> + generated React/Vue/Angular wrappers.

@spain-address/proxy

Hono BFF proxy — GET /api/address-search with CORS.

@spain-address/cascade

Standalone Hono app — GET /api/geo/provincias, /municipios, /cps, /validate-cp.

@spain-address/mcp

MCP server — stdio JSON-RPC with normalize_address and search_addresses tools.

@spain-address/upstash

Upstash Redis Search — retained as explicit opt-in via USE_UPSTASH=1.
